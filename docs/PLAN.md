## 2. 先统一计量与边界

### 2.1 药材数

普通草药、蘑菇、传送晶体均计入药材，每投放一件计一件。盐按实际消耗单位另列，添加基液，加热，研磨，搅拌等操作无耗费。

P1 同时提供两种口径，防止“无限使用盐”制造误导性的少药材配方：

- **直接投料口径**：只最小化这瓶药水直接使用的药材件数；盐设可见上限，并另列用量。无盐模式作为基准。
- **完整生产口径**：把所用盐等中间耗材的制造成本递归展开，比较最终消耗的原始药材。若是外购耗材，则明确购买前提。

在药材数相同的解中，依次优先考虑耗材价值、操作次数和操作容错；这些次级指标不改变第一目标。

### 2.2 耗材价值

P2 的默认基准是原始药材的游戏基础价值，加上实际消耗的其他资源价值。而无需考虑实际采购价格，不考虑商人加价、折扣和购买限制等影响。花园自产原料仍有资源价值，不能在成本比较中默认为零。

自产盐按其生产链摊销成本计价，保留批量产出、余料、前置石头和循环投入；不把一整批盐的成本错误地全压到一次微量消耗上。基液，搅拌，加热，研磨等基本操作无任何收费。

### 2.3 均匀消耗

“均匀”必须有明确参照：默认比较参与生产且允许使用的药材的**原始消耗件数**；可切换为按可获得量或花园产量归一化后的消耗比例。不可种植、尚未解锁或禁止使用的药材不强行纳入均衡集合。

A2 不用任意权重把两个目标混在一起。先计算 A1 的最少药材数，再求一组结果：允许总药材数比最少值多 0%、5%、10% 等时，分别能达到多均衡；同时支持设定均衡容差后，在满足容差的解中最小化总药材数。用户可以据此选择可接受的方案。

主要均衡指标采用各药材归一化消耗率的最大值与最小值之差，并报告最大消耗占比和消耗明细。单次整数批量无法完全均衡时，用多批次混合配方实现长期均衡。

### 2.4 “日产”与销售价值

G1、G2 的首要指标是进入稳定生产后的**长期平均每个游戏日**产出；以游戏进度已经达到末期，所有技能，空间和种子已经充分解锁为前提，并考虑可能的催熟操作、种植槽位、成熟周期、重复收获与不可种植原料均进入约束。

G1 计算贤者之盐的**净产出**：扣除生产过程中消耗的贤者之盐，不能用库存持续下降支撑虚假的高日产。

G2 以实际批发给商人的成交收入为主目标，可以以所有药材种子数充足为前提，要求长期平均下仅依赖花园自给自足，不能依赖稳定从商人处进货原材料。出售的是成品药剂，可以考虑混合多种药效，仅考虑理论价值，而无需考虑买卖价格波动，商人收购上限等因素影响。

这里的“成交收入”统一解释为按固定估值规则计算的理论批发总价值：假定可出售的成品全部售出，不模拟商人到访、资金或收购容量。若批发存在固定系数，则在结果中明确取值；价格波动和议价不作为优化变量。P2 的基础耗材价值用于成本比较，G2 不再把自产原料价值从销售目标中重复扣除。

仅计算“仅靠花园自给”前提，不考虑“允许从商人处补充采购原材料”情景。

### 2.5 花园出产

魔法花园中可以出产药材，水晶洞中可以出产矿物，在花园和矿洞中可以安排一定量的种植点，不同类型的种植点可以种植不同类型的作物和矿物，可以认为各种作物的种子数充足，不需要考虑种子成熟时间，但是要求每种策略中花园和矿洞种植种类固定，不能切换不同作物，所有种植相关技能已经升级至满级。

在正常情况下每种作物与矿物每天可以收获一次。每株作物可以消耗一瓶三级生长药剂进行催熟，每个矿物可以消耗一瓶三级石肤药剂催熟，所有作物和矿石每天只能催熟一次，催熟后可以立即成熟再进行一次收获。

后续模型将“花园自给”统一指魔法花园与水晶洞共同自给。固定种植约束落实到每个种植点：选定种类后，整个策略执行期间不轮作、不换种；可以调整每天是否催熟及采用的酿造配方。种子充足、种植技能满级和不计种子成熟等待均作为用户给定前提，不再建模种子采购与升级过程。

催熟药剂必须由同一生产体系供给，其原料和盐消耗计入资源收支，用于催熟的药剂不能同时计为出售产出。仍需核对一瓶药剂的作用范围、单次收获数量，以及矿物的每日催熟次数上限；作物每日最多催熟一次已经确定。待核对参数显式保留，不自行假定一瓶作用于整个花园或矿物可无限催熟。

## 3. 阶段一：补齐数据并校准酿药环境

现有进展：已导出 58 种实际药材及原始路径、三张基液地图的药效位置和朝向、地图碰撞体、漩涡路径，以及部分酿药设置。三图共 83 个药效位置已与场景对象逐项核对，药效碰撞半径也已提取。已有浏览器 GUI 与初步程序接口。

仍需完成：

1. 核实所有与动作有关的参数及引用资产，包括晶体传送、漩涡、沼泽、倒液、旋转、五种盐、地图边界及力场。
2. 实现完整状态：当前位置、朝向、生命值、剩余路径及其药材段、已有药效、加热状态、持续作用中的盐和已消耗资源。
3. 复现动作与顺序：研磨、投料、部分搅拌、加热、倒液、投盐、传送及作用结束；明确哪些动作可同时发生。
4. 将 GUI 与优化器接到同一套动作语义与数据上，避免界面和求解器各用一套规则。
5. 建立实际游戏对照用例：普通路径、部分研磨、危险区边界、沼泽、晶体起落点、漩涡、各盐、混合药效与失败条件。记录位置、朝向、生命值和消耗。

精度分为三层记录：资源值是否原样提取、算法是否与反编译代码一致、实际游戏回放是否一致。不能因为拿到了精确资源值，就宣称整个模拟器精确。对浮点与帧序造成的误差记录范围；边界解必须保留安全余量或用游戏复核。

**验收：**每种会改变配方可行性的机制有对照用例；同一操作序列在模拟器与游戏中取得一致药效和消耗，位置、旋转与生命值差异在事先明确的容差内。未实现机制不能静默按近似规则参加最优搜索。

## 4. 阶段二：单瓶药水优化（P1、P2）

这是含离散投料选择与连续操作量的搜索问题。先从无盐普通药材开始验证求解框架，再逐步开放晶体、漩涡、盐和不同基液；最终结果必须覆盖所声明的全部允许操作。

1. 为每种药效、等级和基液建立目标区域，包含位置、角度、效果采集和存活条件。
2. 用已有配方、自动路径搜索和局部调整寻找可行解，形成药材数和成本的上界。
3. 按药材件数递增进行有界搜索；使用分支定界、A* 等方法剪枝，连续的研磨比例和动作量由局部优化或区间细分处理。
4. P2 按药材基础价值和自产盐的生产链摊销成本搜索，不引入商人采购价。倒液、加热、研磨、搅拌等动作资源成本为零；搜索需消除无效循环，并明确连续动作的覆盖范围，不能为方便搜索而任意收费或用未经说明的步数上限排除解。
5. 对有希望的解提高连续参数精度并进行完整回放。对边界解测试小幅操作误差，输出容易照做的停点与操作说明。
6. 对每个目标保留资源消耗的 Pareto 候选集：一条在药材数上略差的路线，可能在花园约束或特定药材紧缺时更优，不能提前删除。
7. 优先补齐三级生长、三级石肤药剂的多种资源构成配方，供花园催熟联合优化使用。其最低基础价值配方未必是某个固定种植布局下最合适的配方。

**最优性标注：**有严格下界并排除了所有更优可行解，才称“已证明最优”。固定分辨率搜索只能称“该分辨率下最优”；其余称“当前最好可行解”，报告上界、可用下界、搜索范围和未解决差距。连续控制下的全局最优证明可能很难，不将局部搜索结果冒称全局最优。

**交付格式：**目标药效、等级、基液、配料和盐用量、总件数、基础价值及生产链摊销成本、逐步操作、地图回放、容错情况、最优性状态。

## 5. 阶段三：炼金石与盐的生产网络（A1、A2）

首先完整提取炼金设备、槽位要求、输入药水的精确条件、前置石头、盐产量、可替代输入和是否有返还或副产物。每条生产方式表示为一条“消耗资源→产生资源”的配方。

将阶段二的药水候选配方接入生产网络。不能只给每个槽位选一个局部最省配方：多个槽位可能需要共享稀缺药材，而可用的替代配方会改变全局最优。

- **A1：**用整数规划或混合整数规划选取各药水配方及炼金批次数，在满足目标石头/盐数量的前提下，最小化全链条原始药材消耗。
- **A2：**加入消耗均衡约束，计算均衡程度与总药材消耗的取舍曲线；允许不同批次采用不同配方。
- 精确保留整数批次、剩余库存和产出，分别输出“从零库存做一批”和“连续生产的单位成本”。
- 对可能存在的循环投入使用资源守恒和可执行排程验证，报告启动所需库存；不能只求出代数平衡，却无法从零开始生产。
- 为 G1/G2 保留逐项原料与中间产品的投入产出向量，加入三级生长、三级石肤药剂的生产方式。催熟带来的额外收获在花园层计算，避免既把催熟药剂当作免费投入，又漏扣其原料。

**验收：**生产树展开后，各种原料和中间产品的收支相符，槽位药水均可回放制造，批量与剩余物正确，生产顺序可执行。

## 6. 阶段四：花园模型与最大贤者之盐日产（G1）

以第 2.5 节规则为前提，提取魔法花园和水晶洞满级状态下的种植点数量、各点允许的种类、正常与催熟后的单次收获数量、随机性，以及催熟药剂的作用范围和用量。验证每天次数的重置方式；不加入种子等待、种子供给和技能解锁约束。确认哪些原料能由这两个区域持续获得。

建立固定种植布局与每日库存模型，将正常收获、催熟额外收获、催熟药剂生产、盐和炼金石生产放入同一资源网络。每个种植点选择一种兼容作物或矿物，布局变量为整数且不随日期变化；每日催熟变量受实际次数限制。先用长期平均资源流模型求上界，再用整数批次和多日排程验证可执行性。

目标为最大化平均净贤者之盐产量，同时决定固定布局、各点的催熟频率、催熟药剂配方和炼金配方组合。允许不同日期采用不同酿造配方或催熟安排，但整个策略不能换种。不能先独立选出“最省贤者之盐配方”再搭配花园，因为最适合固定产出结构的配方可能不同。

对每种资源要求长期平均的正常产出、催熟增产和加工产出，至少覆盖催熟、酿药、炼金及最终净产出的消耗。催熟形成“收获→酿催熟药剂→额外收获”的循环，必须计入全部投入，检查启动库存与操作顺序；作物每天最多正常收获一次、催熟后额外收获一次。矿物按核实后的次数上限约束。

若收获随机，报告期望产量，并通过多日模拟评估缺料风险和所需库存缓冲。循环方案可列出有限启动库存，但必须说明其在固定布局下能否自行积累，不能靠持续消耗初始库存维持日产。无法从花园与矿洞再生的必需资源，其长期净消耗必须为零；若因此无法持续生产，报告自给条件下的不可行原因，不改成采购情景。

**交付：**花园与矿洞的固定布局、各点正常/催熟收获、每日催熟药剂需求及配方、炼金批次与配方、启动库存与可执行步骤、平均净日产和瓶颈。对照不催熟与最优催熟方案，说明催熟净增产是否值得其原料消耗。

**验收：**布局全程不变、种植点类型与容量合法、每日收获和催熟次数合法、每瓶催熟药剂有自产来源、各资源库存不出现持续亏空，贤者之盐净产量已扣除内部使用量。

## 7. 阶段五：最大药剂批发收入（G2）

沿用阶段四的固定布局、花园与矿洞自给、催熟和库存模型。提取并验证药效、等级、混合药效的理论估值公式及适用的固定批发系数。明确最终固定估值规则，不引入议价、价格波动、商人到访、资金或收购上限。

1. 生成允许销售的单效与混合药剂候选，纳入核实后的 22、221 等已知配方作基线。
2. 对候选药剂求多种资源构成的酿造配方，计算固定规则下的理论批发价值及完整生产投入。生长、石肤等药剂可以用于催熟或出售，但同一瓶只能分配给一种用途。
3. 联合优化固定种植布局、催熟频率、催熟药剂配方、成品酿造与盐生产，最大化长期平均每日可出售成品的理论批发总价值。内部使用的催熟药剂、盐和前置产品不算销售收入；基础耗材价值作为独立统计，不从这一目标中扣减。
4. 候选组合太多时，先用收益上界筛选，再依据当前稀缺原料的资源价值寻找新配方，迭代扩充候选集。筛选规则须保留可能改善全局收益的配方。
5. 用连续多日模拟检验固定布局和催熟次数是否合法、原料和催熟药剂是否断供、炼金批量是否可执行。假定所有分配用于销售的成品均能出售，不增加销售排程约束。与经典方案在相同满级、自给、固定布局及催熟规则下比较每日理论价值，另列操作量。

**交付：**花园与矿洞固定布局、催熟安排、催熟药剂配方与用量、各销售药剂平均日产及完整配方、每日理论批发总价值、资源收支、启动库存与操作量。

**验收：**满足 G1 同样的自给与固定布局条件；每日理论价值只计算可供出售的最终药剂，内部催熟消耗不重复计入；没有商人采购、收购容量或价格波动变量。

## 8. GUI 与结果浏览

酿药页展示基液地图、药材路径、研磨预览、当前位置/朝向/生命值、目标药效、盐用量、逐步回放和截图对照。每个优化结果可一键载入回放。

配方比较页同时展示药材数、基础价值成本、各药材消耗和操作容错；可以切换无盐、有限盐、完整生产成本等约束。炼金页展示生产树、每批投入、产出与余料。花园页同时展示花园与矿洞的固定种植位置、正常与催熟收获、催熟药剂投入、库存变化、贤者之盐净日产或药剂每日理论批发价值。

每份结果保存游戏版本、数据指纹、用户模型假设、允许资源、基础价值与固定批发估值规则、固定布局、催熟参数、启动库存、求解设置与最优性状态，支持 JSON/CSV 导出及可读操作清单，使结论可以重跑和核对。用户给定的简化前提与从游戏提取的机制分别注明来源。
