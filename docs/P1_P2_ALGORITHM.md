# P1 / P2：算法、边界与执行目标

更新时间：2026-10-01。用户最新盐折算规则优先于此前计划。活动目标：覆盖 41 种单效药效 × I/II/III 级，比较三种基液，分别呈现无盐与含盐的 P1/P2 配方、可回放操作、上下界与最优性状态。后续再接炼金需要的混合药水。

## 1. 目标函数

设实际药材件数为 N，各药材件数为 n_i，基础价值为 p_i；四种允许盐的实际消耗为 s_void、s_sun、s_moon、s_life。

盐等价份数 Q = s_void/200 + s_sun/100 + s_moon/100 + s_life/50。

- P1：最小化 N + Q；无盐模式 Q=0。
- P2：最小化 Σ(n_i × p_i) + 水之盖基础价值 × Q。
- 禁用贤者之盐。不展开制盐实际成本，不加入商人加价或操作费用。
- 盐折算按比例计算，Q 不向上取整；实际用量是否必须为整数是动作模型问题，不能与费用取整混为一谈。游戏盐的逐单位溶解回调与未结束旋转需要继续核对。
- 所有允许基液均参与比较。精确等级分别求解，不能把三级药效直接当成一级/二级结果。

## 2. 为什么不能直接穷举所有动作

离散部分是药材/盐选择、基液、加料和采集顺序；连续部分是研磨、搅拌停点、倒液时间和强度、风箱输入及各动作的时序。完整状态还包括剩余路径、药材段类型、生命值、炉温、朝向、已收集药效和持续作用。

相同位置的两条路线可能有不同剩余路径或生命值，因此不能只按地图位置合并状态。免费动作可能重复，也不能随意限制操作次数后宣称全局最优。

采用两条互补的计算线路：**可行解搜索产生上界；保守松弛与分支定界产生下界和排除证据**。搜索失败仅代表尚未找到，不代表不可行。

## 3. 线路 A：快速找到和改进可行配方

### A1. 多分辨率路线搜索

建立危险区/沼泽的空间索引与粗网格，只用于快速评估候选动作。预采样药材曲线，按少量研磨档位生成候选移动；晶体与普通药材分开处理。不同基液独立搜索后比较结果。

采用加权 A* 优先扩展“已花费资源 + 到目标的启发式估计”较小的状态。P1 按药材等价消耗排序，P2 按基础价值排序。加权优先级、位置量化和搜索预算用于提速，只能产生候选，不是最优性证明。逐轮细化网格、研磨档位，扩大路线类型与预算。

搜索不仅保留一条路线：维护药材数、基础价值、各药材消耗的 Pareto 候选，并跨目标共享已发现的路线。无盐可行配方也是含盐模式的可行上界。

### A2. 连续控制优化

固定一条离散投料/动作骨架后，优化研磨比例、最后搅拌比例、倒液量和旋转量。先用粗几何筛选，再用真实共用引擎评估。当前试算使用无梯度 Nelder–Mead 调整末段控制；接下来增加多起点、逐段调整和自适应区间细分。

三级目标的有效区域很小，必须按位置与朝向共同评分。一级、二级有明确等级区间：沿路线找较早采集点，必要时独立搜索更便宜的路线。

### A3. 验证与容错

从合法基液中心重放全部操作，检查实际资源、每步存活、剩余路径、加热后的最终药效与等级；不能直接赋值到目标位置。候选必须经共享 `engine/` 验证才能进入正式候选报告。

进一步扰动研磨、搅拌、倒液和盐用量，报告容错，而非只给一组小数。GUI 回放与算法使用相同动作语义。现有引擎验证不等于实际游戏验证，游戏仍禁止启动。

## 4. 线路 B：缩小空间并证明到什么程度

### B1. 由当前上界推导资源上限

假设已经找到目标值 U 的可行配方，那么任何改善解都必须低于 U。

- P1：N≤floor(U)，并分别有 s_void<200U、s_sun<100U、s_moon<100U、s_life<50U；扣除已用资源后，上限继续收紧。
- P2：第 i 种药材件数不超过 floor(U/p_i)；盐上限由其单位折算价值同样推导。
- 因此不需要拍脑袋规定“每瓶最多 1000 盐”或无限制搜索更多材料。整数边界在严格改善/并列解时分别处理。

这些上限只限制付费资源，不自动给免费动作设置任意次数上限。

### B2. 可证明的下界

初始安全下界很弱：普通目标不在基液中心；无贤者之盐且起点不接触漩涡时，零药材不能离开中心，所以至少需要一件药材。P2 至少承担一种可用药材的最低基础价值。此结论需逐目标确认起点与免费动作条件。

随后对低件数输入构成和连续控制区间建立放松后的可达集合，用分支定界逐块排除。危险区可以暂时忽略以扩大可达集合；能证明这个更宽松的问题仍到不了目标，才可以安全排除真实路线。晶体、免费漩涡和盐旋转必须纳入放松，不能用“直线距离/单药材最大位移”当作覆盖所有机制的严格下界。

先集中证明低件数问题：零件、单件、两件等，因为这些最容易排除，且能为 P1 提供有效整数下界。无盐 P1 若有一件药材可行解且证明零件不可能，在当前动作模型下件数即最优；P2 和含盐 P1 仍需比较其他构成与盐用量。

### B3. 连续区间分支定界

对固定骨架的连续参数盒计算包含真实轨迹的外包围；只在包围无法接触目标、资源下界超过 U 或所有轨迹都会失败时剪枝。优先细分最影响药效对齐或碰撞的参数。在不能提供保守包围的机制上保留未排除分支，不用采样失败充当证明。

区间分支定界与完整免费动作可达闭包尚未实现，是证明线路的主要工作。全局最优标签必须同时满足动作范围完整、区间包围可靠、所有更优分支已排除。否则报告下界 L、当前上界 U 和未解决范围；不能把计算预算耗尽称为完成证明。

## 7. 接下来的具体算法目标

1. **目标：补全能影响后续行动的状态。** 目标朝向、动画朝向和旋转进度已接入共用引擎；状态同时保留未走路径、药材段、生命值、热量、已采集药效及资源。源码对照和新增动作顺序回归通过，旧配方已重新回放，492 行展示结果对应 231 条不同配方均通过；组件调度及输入模型仍需继续核对。
2. **目标：以更广的合法动作寻找更低上界。** 扩展事件点动作：路径途中停止、加料、倒液、加盐、加热和漩涡传送。启发式束搜索保留多个状态与资源构成，固定骨架后多起点连续优化。事件点离散与束宽限制仍属于近似搜索，必须记录限制，不能作为完整性证明。
3. **目标：安全排除比当前配方便宜的资源构成。** 按现有上界枚举低件数或低价值构成，构造包含真实轨迹的可达集合外包围。只在放松问题仍不可达时排除；普通路径、晶体、旋转、倒液和免费漩涡闭包缺少可靠外包围时，分支保持未解决。
4. **目标：对可证明的范围缩小 L/U 差距。** 固定骨架后对连续参数盒进行区间分支定界，优先细分影响位置、角度、碰撞和采集等级的参数；免费操作闭包与骨架覆盖没有证明前，只报告限定范围的证书。
5. **目标：交付可复核且容易操作的结果。** 每项显示主目标成本、下界、差距、证明范围、完整操作、容错采样及一键 GUI 回放；在实际投入资源不增加时优先改进容错。

昂贵的完整几何模拟留给有希望的候选与验证；曲线缓存、空间索引、跨等级/目标共享候选和当前上界剪枝降低计算量。粗网格及量化状态只用于启发式线路；证明线路不能依赖它们排除真实状态。

## 8. 途中旋转的单件试算

optimizer/rotated_single.py 先从合法基液中心加入一件普通药材，加入整数日/月盐批次，等待指定时间，再部分搅拌及倒液；可付费加入相反盐恢复瓶子朝向。覆盖三种基液，保留实际盐账单；晶体、不同加盐时点和更多投料顺序尚未在此试算中枚举。几何旋转曲线只提出起点，实际带热量与旋转动画的回放决定可行性。

连续优化与最终回放现共用动作执行函数，修复了连续评估只识别虚无盐、把等待当成倒液的局限；新增回归用例核对带日/月盐与等待的连续优化结果和 GUI 调度器一致。优化器依赖运行环境中全套 64 项检查通过；普通无 NumPy 环境跳过这一项数值优化检查。

本轮先试火、冰霜、闪电和治疗，盐网格为 1、20、40、60、80、100 单位，等待 0.025 或 0.06 秒，每个连续起点最多 45 轮。此网格与预算是计算设置，不能作为排除其他解的证据；后续根据改进情况细化整数盐搜索。

容错采样现在记录引擎/数据指纹及采样器版本，并对等待时间施加 ±0.005 秒扰动。报告不再把缺少版本信息的历史采样作为当前容错证据；已启动重新评估。旧采样文件保留历史内容，新采样逐条覆盖对应配方。新增检查确保旧引擎或旧采样器的结果不会被视为当前证据。

首个时序搜索检查点为葡萄酒基液的治疗：52 次连续细化产生 4 条保留记录（P1/P2 各一级、二级），全部通过独立 GUI 调度器验证。其消耗为一件生命叶加一单位旋转盐，P1=1.01、P2≈6.264；比已有无盐一件生命叶的价值 6 更高，因此不会替换正式最好结果。这证明新动作骨架可执行，并不证明带盐配方更便宜。其余基液和目标的试算继续运行。

## 12. 区间排除的首个基础模块

## 13. 剩余路径的区间状态传播

`CarriedPathBox` 保留当前位置与固定点数的剩余路径包围。零角度移动保留 `move_remaining_path` 和 `rotate_about(..., 0)` 的二进制运算顺序，包含减去/加回枢轴的舍入；追加药材按局部路径的 `path[1:]` 加到原路径末端，不使用瓶子角度。局部药材路径必须预先有可靠包围，本模块不证明生成过程。非零或跨零角度区间明确抛出未解决标记，不能被上层解释成不可行。

三个新增用例覆盖不确定移动位置、实际部分搅拌后多帧倒液及再追加药材、未支持旋转的明确拒绝。区间模块六项检查、全套 75 项检查通过。这是固定拓扑的动作传播原语；实际倒液测试把真实移动的位置传入包围，不代表已实现倒液时间/速度到位置的区间积分。路径消耗和点数变化、热量、碰撞、旋转及免费动作闭包仍缺失，不产生新的配方下界或全局最优证书。

## 14. 单步普通搅拌的拓扑分支

`CarriedPathBox.stir_step` 采用归一化步长区间与沼泽因子区间，通过两次 `lerp` 包围 intended/actual，再包围 `actual - intended` 对剩余路径的平移。它同时保留当前点、删除当前点、极短段直接删除三种拓扑，避免在 `consumed >= segment - 1e-10` 边界上凭近似距离错误合并分支。

步长与沼泽因子可放松为整个 [0,1]，因此不依赖有限停点采样；但这只是单次内部迭代的包围，不是完整搅拌动作闭包。尚未由总搅拌量、路径长度和 spacing 推导迭代次数与步长范围，也未传播盐动画、时间/热量、力场校正、晶体、药效或生命值。调用方必须确认普通药材且没有未包围的外部影响；力场 correction 参数暂时明确拒绝。不能用该模块的缺省分支直接排除所有游戏动作。

新增验证覆盖沼泽因子与步长区间、删除前后点数、极短段分支和不支持输入；另逐步观察合法中心投放 Firebell 后冷态搅拌的实际引擎迭代，核对位置和剩余点全部位于对应拓扑包围中。区间模块九项、全套 78 项检查通过；逐步实测只验证原语，没有证明重复迭代的可达闭包。当前药水成本下界不因此提高。

## 15. 总搅拌量驱动的几何循环包围

`optimizer/ordinary_stir.py` 由剩余路径长度区间乘以搅拌比例区间得到删除预算；每步包围 `min(target, segment, spacing)`、归一化步长、目标预算递减和行进时间，保留零长度段及删除点边界分支。节点预算耗尽输出具体未解决状态，不能作为排除；若确定 consumed 就是 target，保留同一浮点数相减为零的关系，避免普通区间减法凭空产生无限余量分支。

路径长度包围专门核对了当前 Python 运行时：`distance_box` 采用 [CPython hypot 的小于 1 ulp 误差约定](https://docs.python.org/3.12/library/math.html#math.hypot)，包围精确平方根后向两侧各扩大两个相邻 binary64 值；`float_sum_box` 按 [CPython 3.12.14 的浮点 sum 源码](https://github.com/python/cpython/blob/v3.12.14/Python/bltinmodule.c) 包围补偿求和与比较分支。它不是 Unity 的距离实现，也不假设 Python 内置 sum 是普通累加。补偿模块只接受 CPython 3.12；其他版本返回未解决。

三个新增测试覆盖当前真实药材剩余长度、不同数量级距离、补偿求和、短循环全部参数包围、极短段与预算耗尽。测试中短循环对整个搅拌比例区间生成终态包围，再用几个实算参数验证包含关系；采样本身不构成区间正确性的证明。全套 81 项检查通过。

**适用范围仍有限：**只包围指定 speed/factor 的普通几何搅拌循环，不执行环境演化，不涉及力场、晶体、热量、生命值、药效、漩涡和盐动画。真实游戏的完整搅拌不能直接调用后宣布不可达；这些缺失机制必须由调度器明确检查并留作未解决。当前没有提高药水成本下界或颁发新的最优证书。

## 16. 接到真实地图的冷态搅拌适用检查

`optimizer/cold_stir.py` 接受固定当前状态的普通路径和连续搅拌量区间。只有起点存活、热量为零、无旋转控制器、没有晶体段且零输入不产生热量时进入计算。对各次当前位置、intended 位置及终态包围检查地图边界、区域接触和力场内部。区域索引的除法/取整用区间覆盖，按当前引擎真正会查询的全部格子取候选；圈/盒接触比较也保留浮点运算顺序。力场内部用多边形射线比较的固定奇偶性确认，模糊边界保留未解决。它核对当前引擎，不证明索引与 Unity 物理相同。

## 19. 最小项条件分支与保守拓扑合并

`minimum_cases` 覆盖 `min(target, segment, spacing)` 的每一个可能最小项。各分支限制被选项上界不超过所有项的最大可能值，并提高其他项下界；平局可以重复覆盖，不能遗漏。target 分支保留完全消耗预算为零、segment 分支保留归一化步长为一的关系；其余差值因真实 target >= consumed 可收紧为非负。

直接保留所有最小项分支会重复放大微小舍入差异。现在按循环深度与剩余点数，用坐标逐项 hull 合并位置、后续点、剩余量和时间，包含每条输入状态。这是放松后的可达集合合并，**不宣称真实状态等价**，也不能直接用于包含晶体、路径段类型和其他持续作用的完整酿药状态。合并产生的假状态只能增加未解决范围，不能作为排除依据。

改动后 [0.05,0.06] 的真实地图示例获得完整终态包围：一个参数盒、10 个循环节点，未解决为空；此前 1730 节点仍未完成的记录已被更新源码重跑结果替换。新增最小项切换/平局覆盖与三个实际搅拌量的完整回放对照；全套 91 项检查通过。两份示例的输入/源码哈希已刷新。它仍只证明固定状态的一次冷态普通搅拌包围，没有增加药水成本下界或证明全局最优。

## 20. 冷态倒液与后续搅拌的连续操作包围

`optimizer/cold_pour.py` 在固定强度、零朝向、冷态普通路径下，对倒液时长区间分支为完整帧与最后部分帧，包围速度、满强度加速、中心距离、插值及剩余路径平移。最后部分帧用舍入误差界确认下一次循环停止；时间比较、距离跨零、潜在区域接触或预算不足无法确认时保留未解决。精确中心位置和插值比例一的抵消关系单独保留。它不处理非零朝向倒液、盐动画、晶体或热态漩涡。

路径长度的补偿求和进一步保留抵消关系：每个补偿增量等于三次运算舍入误差的组合，而不是三组独立的大范围坐标。新误差界与原运算区间取交集，避免倒液后的不确定平移让路径长度包围无谓膨胀。它依赖当前 binary64 最近舍入模型，与 Unity 精确一致仍未证明。

复现命令 `python -m optimizer.cold_pour`：合法中心投放一件完全研磨 Firebell，先搅拌 .06，强度 .5 倒液 [.005,.015] 秒，再搅拌 .001。结果 `result/search/cold_pour_stir_certificate.json` 用五节点获得完整运动终态包围；时间字段从倒液开始计，不包含固定前缀。记录包含源码/数据哈希、运行时、参数、位置/后续点数及未解决原因。三个实际时长的组合回放全部位于包围中。

新增验证覆盖部分/完整帧边界、满强度时长跨越加速阈值、中心、非零旋转拒绝、预算耗尽，以及倒液后继续搅拌的路径保留；全套 95 项检查通过。两份旧搅拌示例也按更新的补偿模块重新生成。完整运动包围不表示已完成药效采集或排除了更便宜配方，P1/P2 下界不因此提高。

## 21. 连续研磨与投料拓扑覆盖

`optimizer/ingredient_intervals.py` 对当前引擎确定生成的完整物理采样路径，传播研磨比例到有效截断比例。它覆盖所有可能截断线段、每段的连续插值位置、不同路径点数及 `fraction >= 1` 的完整路径分支。截断目标与遍历累计长度分别遵循当前运行时的补偿 sum 和普通累加；严格继续条件采用 nextafter 保留全部 binary64 目标值。截断插值不擅自夹到 [0,1]，保留原引擎边界舍入可能产生的微小越界。预算不足留作未解决，晶体暂时明确不支持。

运行 `python -m optimizer.ingredient_intervals --audit-all`：49 种普通药材在研磨 [0,1] 下均完成路径包围，每种额外核对7个实际研磨量，共343次全部被包围；9种晶体记录为未支持。结果在 `result/search/ingredient_interval_audit.json`，含输入/源码哈希。样本是附加检查，不是整个区间覆盖的证明方法。

默认运行 `python -m optimizer.ingredient_intervals`：水地图 Firebell 研磨 [.49,.51]、搅拌 [.05,.06]，2个投料路径分支、16个搅拌节点得到完整运动终态包围，结果在 `grind_stir_certificate.json`。九组实际研磨/搅拌组合均在包围中，另覆盖满研磨与预算失败；全套98项检查通过。采样路径生成自身仍是当前引擎的确定性输入，没有证明 Unity 使用同一浮点采样规则；也未覆盖后续热态采集、盐旋转、晶体或免费动作闭包，因此没有新增药水成本最优证书。

## 22. 晶体的截断路径与条件传送终点

研磨包围新增显式 `allow_crystal=True`，对晶体使用 graphics 间距，与 `PotionSession.add` 一致；默认入口仍拒绝晶体，防止将传送路径错误地交给普通搅拌。9种晶体在 [0,1] 研磨下全部路径拓扑完成包围，45个路径样本核对通过。

`optimizer/crystal_intervals.py` 依据原引擎的传送停止条件，包围最终 traversed 的长度范围，枚举可能的最后线段并包围插值。补偿总长度与普通段起点累计值分开计算，最后插值不擅自夹到一；极短路径保留无移动分支，分母跨零则留作未解决。已完成晶体段被删除，后续路径保持原坐标，与漩涡到达后的平移行为分开处理。

复现 `python -m optimizer.crystal_intervals`，记录在 `result/search/crystal_interval_certificate.json`：9种晶体、45个路径样本、27组固定研磨的条件传送终点包围。实际传送对照用例关闭伤害区域，只检查完成传送的终点与未移动尾路径；它不证明原地图路线能存活。完整源码/数据哈希与运行时保留，全套100项检查通过。

本模块以传送已完成、无持续旋转为条件，没有证明速度、耗时、淡出/淡入碰撞、健康或 Unity 帧调度。它是成功配方到达位置的放松包围，而不是可行配方或全局最优证书。下一步补齐三阶段时间与伤害接触；旧普通药材与研磨/搅拌记录也已按新入口源码刷新。

## 23. 冷态晶体三阶段时间与额外伤害

`optimizer/crystal_timing.py` 按当前冷态引擎常量计算淡出/淡入的离散进度和帧数；传送移动利用路径总长度区间包围满足停止条件的帧数，并按原始 `elapsed += dt` 累计总时间，避免帧数乘 dt 的不同舍入。进度停滞或帧预算不足返回未解决。27组晶体/研磨用例的阶段帧数与总时间都被包围；对照中关闭危险区，使测试能完成全部阶段。

`optimizer/crystal_damage.py` 对每个固定冷态淡入/淡出进度，计算原始半径和区域查询格子。候选区域用并集判断可能接触，只有在全部格子都有对应碰撞体且盒内必接触时才算保证接触。强危险区优先于弱危险区；完成帧的额外伤害为零，淡出最后帧不查询区域。每帧可能的额外伤害取区间，再包围总额外伤害。接触不确定、范围过宽等保留未解决。

伤害对照使用覆盖地图的人工强危险区域，并关闭 `_health_step` 的伤害中止来观察完整原始淡出/淡入参数；只比较额外伤害计算，不假装这些路线在原地图存活。新增边界接触反例检查“可能”与“保证”分开。全套104项检查通过。

晶体记录已更新：9种晶体、45个路径样本、27组固定研磨均完成端点和冷态阶段包围，附每帧半径、可能/保证接触、额外伤害、进度、时间及完整源码/数据快照。`allColdPhaseEnclosuresComplete` 仅表示这些条件下的包围完成；survivalProved、timingProved（完整未限定时序）、actualGameVerified 仍未成立。热态、旋转动画、生命值与地图边界仍需接入，未新增药水成本证书。

## 24. 晶体模型的生命值与地图包含证书

`optimizer/crystal_survival.py` 将静止淡出/淡入的额外伤害接到生命值区间，并按区域的可能/保证接触分支处理瞬时回血。最低生命值保留起始值与全过程，不能用后来回血抹掉先前死亡；多个终点分支用 hull 合并最低生命值，不把互斥分支当作先后执行。无法包围的路径/生命值保留未解决。

传送沿途枚举各线段的全部可能插值，按地图下边界包含、上边界排除规则检查区域盒。冷态移动层不触发危险区，水/油按原引擎瞬时回血；葡萄酒使用起终点距离的三角不等式计算保守回血下界，扣除坐标差、hypot、乘法及逐帧生命值相加的舍入损失。非负回血达到1后保持1；此下界不把曲线路径总长直接当成实际逐帧移动距离。

水地图从合法中心、满血起步、9种晶体各0/.5/1研磨共27组冷态固定用例，均证明当前引擎模型内的最低生命值严格大于零且在地图范围内；此次对照保留真实危险区与健康中止，全部正常完成且健康落在包围内。油/葡萄酒以较低起始生命值验证回血，人工致死区域与地图上边界反例不获存活证书。全套107项检查通过。

晶体记录新增每例 `survivalProvedUnderModel`、最低生命值和条件终态生命值，并保存更新源码快照。根级未限定存活/实际游戏验证仍为false：这些证书不涵盖热态、旋转动画、同步操作或 Unity 时序，不证明某种药水成本最优。另发现单件搜索的晶体几何种子仍使用默认物理采样间距，而实际投料使用图形间距；下一步修正前端采样一致性并继续低资源搜索。

## 25. 单件晶体的采样一致性与多起点搜索
