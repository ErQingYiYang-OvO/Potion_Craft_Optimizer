# Potion Craft 2.0.2 酿药实验台

这是用于提取本机游戏数据、试走酿药路线和与游戏截图对照的独立项目。游戏安装目录只读取，不修改。本项目目前是**校准中的实验台**，尚不能用来宣称所有配方的数学最优解。

## 启动

在本地完整项目的主目录运行 `python playground/serve.py`，然后打开 <http://127.0.0.1:8765/>。只需 Python 标准库。浏览器读取主目录 `data/` 中的 JSON，并通过本地服务调用 `engine/brew.py` 执行操作。运行 `python -m engine.brew` 查看最小示例，运行 `python tools/validate_data.py` 核对提取数据。完整项目计划见 [实施计划](../docs/PLAN.md)。远端当前先发布文档，尚未同步运行源码与数据。

## 界面使用

- 左侧地图、加入药材、搅拌、鼓风与加热、加入基液、加入盐、配方文件、漩涡观察、截图对照、当前状态和操作记录均可独立折叠，刷新后保留展开状态。
- 药材选择器显示全部 58 种药材的游戏中文名称、原版小图和基础价值；可按中文或内部英文标识搜索，支持方向键、回车和 Escape。
- 三张地图的药效点显示对应原版图标，放大后显示中文名称；状态与操作记录也显示中文。
- 中文名称来自游戏内置本地化表，药材图像来自库存图标，药效图像依据原版纹理层与默认颜色合成。导出文件使用稳定的内部标识，便于重放。

## 已从本机 2.0.2 资源提取

- 58 种可用药材，包括 9 种传送晶体；另有 1 个 `Default` 资产。每种药材有原始贝塞尔曲线、未研磨比例、标价和相关研磨参数。
- 水、油、葡萄酒三张地图，分别有 41、21、21 个药效点；位置、朝向、基础价格和基液回血参数来自资源。
- 地图碰撞体：水图 15,921 个强危险区；油图 2,769 个强危险区和 4,880 个沼泽区；酒图 1,131 个强危险区、14,553 个弱危险区和 94 个治疗区。地图边界与水图 80 个、油图 19 个漩涡的序列化几何也已导出。
- 13 类酿药设置，包含路径采样间距、药效评分曲线、搅拌速度、危险区损伤、盐、倒液与漩涡参数。原始盐资产见 `data/salts_full.json`。
- 83 个药效的圆形碰撞半径均为 `0.7900000214576721`，已逐个从场景子物体核对；药瓶碰撞半径为 `0.7400000095367432`。
- 风箱实例的升温/降温曲线、采集后温度，以及倒液降温曲线：见 `data/bellows_controls.json` 与 `data/pouring_controls.json`；三图力场与漩涡的父级坐标核对结果见 `data/level*_transform_audit.json`。

## 当前模拟范围

共用引擎与浏览器已支持普通药材路径的贝塞尔采样、指定研磨比例、部分搅拌、倒液、日/月盐旋转、生命盐、虚无盐、收集药效及状态导出。剩余路径在操作间保留；已投放路径随药瓶移动与旋转，新药材按自身方向追加在剩余路径尽头。浏览器可切换三张地图，显示危险区、漩涡和路线，并可把本地游戏截图叠在地图上调节位置、大小和透明度进行肉眼对照。截图不会上传。

晶体已可加入：紫色点线表示传送段。搅拌触发整段传送，后接路径保留且需再次搅拌；生命值按淡出、穿越、淡入计算。导出文件包含逐帧传送记录。

贤者之盐已可操作：按最近未采集药效自动移动与旋转，保留剩余路径，受沼泽减速。本操作假设指定数量同时溶解，并等待全部生效；逐粒投放及与其他动作重叠尚未实现。

力场与越界已接入：搅拌时按多边形最近点修正药瓶目标；超过允许距离或走出地图背景矩形会失败。失败状态保留位置、路径和原因，可撤销、清空或导出。

风箱与漩涡已接入：快速鼓风或按指定累计下压角度/时间鼓风；满热时自动采集药效并降温到零。等待会继续自然冷却与余热推动的漩涡运动；搅拌、倒液和贤者之盐过程中也会推进热量和漩涡状态。漩涡会把未消耗药材路径一起平移到出口，与晶体保留后续路径世界坐标的行为不同。开始传送时停止当前输入，并等待整次传送完成。

## 观察与重放

“漩涡机制观察”可从指定漩涡旁开启一个独立场景，预置 80% 炉温和一份 Waterbloom。此起点明确标记为观察场景，不能用于合法配方。可先等待一秒查看螺旋移动，再等待一秒查看最近漩涡的传送。“聚焦全部行进轨迹”同时显示此前移动与传送路径，药瓶外圈按实际碰撞半径绘制。

导出文件现在包含机器可读的 `operations`。选择“导入并重放操作”，引擎从起点重新执行并返回新结果；旧版只有状态而没有操作的文件不能重放。可导入 `docs/examples/vortex-observation.json` 快速复现示例。重放使用当前引擎版本，因此校准后的结果可能发生变化。

**尚未完成精确校准：**Unity 固定物理更新与组件更新顺序、触发回调滞后、视觉旋转 tween、float32 舍入、传送中插入其他操作、盐逐粒到达与多种控制同时输入。风箱角度是累计正向角度输入，尚未模拟实际风箱臂的下压/回弹运动约束。晶体与漩涡传送使用近似帧调度并等待整段完成；环境更新采用显式的“炉温→药效采集→漩涡”顺序，不能宣称与 Unity 实际更新顺序相同。39 项回归检查通过，详见 `docs/BREWING_AUDIT.md`。

后续继续只读核对 `reference/decompiled/` 中的动作状态机，并移植未完成机制。用户已禁止启动和交互游戏本体，因此画面对照仅能使用用户提供的观察与截图。只有完成声明范围内的机制校准后，才适合运行优化算法。
